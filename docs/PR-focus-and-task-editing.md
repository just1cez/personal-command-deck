# 推进界面专注时长手动输入 / 关联待办，今日待办随时可改

## 背景

这次改动围绕日常使用中的三个小痛点，都发生在「推进」和「聚焦」界面：

1. 专注时长以前只能靠加减号按 5 分钟为步进调整，想设 37 分钟得连点很多下。
2. 专注时长只会累计到「项目」，但很多时候我想知道某个具体待办上到底花了多久。
3. 今日待办一旦创建就无法改字，写错或想微调只能删掉重建。

目标是在**不改动现有功能代码路径**的前提下补齐这三点，所有新能力通过可选字段 / 可选属性注入，保证旧本地存档照常加载。

## 改动内容

### 1. 专注时长支持手动输入

- 项目专注弹窗的时长步进器中间，数字改为可直接键入的输入框，敲入即用（如 37）。
- 失焦或回车时自动收敛到 5–120 分钟合法区间；回车只确认输入、不会误触发「开始专注」。
- 加减号按钮保持原样，仍以 5 分钟为步进。
- 修复了输入框可点击区域过窄的问题：现在整格都能点入并出现光标（此前只有中间约 67px 可点）。

### 2. 专注开始前可关联一个今日待办

- 专注弹窗新增「关联今日待办」下拉，列出今日**未完成**的 Top 3 与普通待办，首项为「不关联待办」。
- 选中后，本次专注结束/暂停/重置/自然结束时，时长会**同时**记入所选待办和原项目 —— 项目级统计与提示保持不变，只是新增了待办维度。
- 今日面板对应的任务行会显示一个「N 分」小徽章，标出累计专注分钟；未专注过或明日 / 收据面板的任务不显示徽章。

### 3. 今日待办随时可改

- 在今日面板双击任务文字即可就地编辑：回车 / 失焦保存，Esc 取消，空内容不保存也不删除任务。
- 仅今日面板（Top 3 + 普通待办）启用，明日计划与收据面板保持只读。

## 技术要点

- 数据模型新增可选字段：`Task.focusSeconds?`、`FocusSession.taskId?`（`src/types.ts`），旧对象天然兼容。
- 归一化兜底集中在 `src/dashboardState.tsx`：`normalizeTasks` 为缺失字段补 `focusSeconds: 0`，focus 归一化校验并补 `taskId`，覆盖本地加载与备份导入两条路径。
- 关键正确性点：专注时长是在后续「切换 / 暂停 / 重置 / 自然结束」这 5 个时机结算的，因此「本段专注属于哪个待办」被存进 `focus.taskId`，并在全部结算点新增与项目对称的 `settleFocusTask`，把时长并行记入待办；暂停保留关联、重置清空关联，无重复计数。
- UI 复用现有组件与模式：下拉复用 `ThemedSelect`，待办编辑与徽章延续 `TaskRow` 的可选属性扩展写法，未改动既有调用点。

## 涉及文件

- `src/types.ts` —— 新增可选字段
- `src/dashboardState.tsx` —— 归一化 / 迁移兜底与默认种子
- `src/App.tsx` —— `settleFocusTask`、5 处结算点、弹窗关联待办选择器、任务行传入累计分钟
- `src/components.tsx` —— `TaskRow` 就地编辑与「N 分」徽章
- `src/App.css` —— 输入框可点区域、徽章与选择器样式

## 测试与验证

- `npm run lint` 与 `npm run build` 均通过。
- 通过无头浏览器端到端驱动真实界面验证：
  - 专注时长可直接键入并收敛到 5–120，加减号仍按 5 分钟步进，整格可点入。
  - 关联待办后暂停，待办与项目**各自**记入同一段时长；「不关联」时任何待办都不受影响、项目照常记录。
  - 累计≥1 分钟的待办行显示「N 分」徽章，0 分钟及明日面板无徽章。
  - 今日待办双击可改、回车 / 失焦保存、Esc 取消、空内容不保存；明日 / 收据面板保持只读。
- 兼容性：载入不含 `focusSeconds` / `taskId` 的旧本地存档，字段自动补默认值，无报错、界面正常渲染。

## 兼容性 / 影响面

- 本地 `localStorage` 结构向后兼容，无需清数据或手动迁移。
- 备份导入 / 导出无需改动，新字段随整体状态序列化。
- 现有专注 / 项目统计、任务勾选 / 删除 / 排序、明日与收据面板等功能均无回归。
